# zenzによるオフラインAI変換

SumireのJNIブリッジと、そのコミットが参照するazooKey版llama.cppを利用します。固定リビジョン・モデルSHA-256は `UPSTREAM.json` に保存しています。

- モデル: [zenz v3.2 xsmall Q5_K_M](https://huggingface.co/Miwa-Keita/zenz-v3.2-xsmall-gguf)、20,970,304バイト。
- Android: arm64-v8a／x86_64、CPU、コンテキスト1024トークン、区間ごとの生成上限128〜384トークン、最大4スレッド。
- アプリ実行時には通信せず、同梱モデルをアプリ内ファイルへ検証・展開します。辞書とAIは別スレッドで並列に動かします。読み・カタカナまたはキャッシュを即時表示し、辞書とAIは返ってきた順に統合します。
- 入力前後の文字列を端末内の文脈として使い、辞書の第一候補を保ち、その次にAI候補を追加します。辞書準備前の仮の読み候補のみの場合はAIを先頭に表示できます。AI候補には「AI」を表示し、重複を除きます。Sumire全体の学習・予測・再順位付け機能の移植ではありません。
- 入力・削除・確定・記号切り替え・設定変更・画面破棄で旧推論をキャンセルします。遅れた結果は要求番号でも破棄します。
- 読みと前後文脈が同じ32件をメモリにキャッシュします。AI処理のスレッド優先度を辞書処理より低くし、UIと辞書の表示を優先します。
- モデル準備失敗時も辞書変換を使えます。設定でzenzをOFFにでき、初期値はONです。
- JNIブリッジとllama.cppはMIT、モデルはApache-2.0です。通知はアプリの「設定→ライセンス」から表示できます。

## ビルド

初回は `scripts/prepare-zenz.ps1` をオンラインで実行してください。固定コミットのllama.cppと固定SHA-256のモデルを取得します。以後は `scripts/build-prototype.ps1 -Offline` でビルドできます。Android SDKにNDK 28.2.13676358とCMake 3.22.1を用意します。別のSDKに入っている場合は `-NativeSdk` で指定できます。

## 実推論の確認範囲

Windows上で同じJNIコードをビルドし、同梱GGUFモデルを `ZenzSmoke` で読み込み、次の変換を確認しました。

- にほんご → 日本語
- きょうはいいてんきです → 今日はいい天気です
- がっこうにいきます → 学校に行きます

これはホストでの実推論確認です。Android向けの両ABIはビルド・JNIシンボルを確認しますが、接続端末がないため、Android実機の表示・応答速度・推論は未確認です。

Windowsでは `zenz/src/main/cpp` をVisual Studio 2022用CMakeで構成して `zenz` をビルドし、`zenz/src/main/java` と `zenz/src/test/java` の `ZenzSmoke` をJDK 17でコンパイルして実行できます。ログの出力先だけを切り替え、推論処理はAndroid版と同一です。

## 長文と候補検証（1.1.4）

かなを最大64コードポイントずつ変換し、リテラルはそのまま保持する。AIの対象は全体2048文字までとし、辞書の32文字制限は撤去した。左文脈は変換済み部分の末尾64コードポイント、右文脈は最終区間のみ最大32コードポイントを使う。モデル出力に付く前後の空白・改行は取り除き、内部の改行・制御文字は拒否する。

同梱モデルの長文推論では文の一部が欠落する例があったため、辞書の読み経路で入力全体と出力全体が対応するか検証し、不一致ならAI候補を表示しない。辞書の第一候補を保ち、未検証のAI出力で置き換えない。辞書にない固有名詞などもこの検証で除外される場合がある。モデル更新やSumire全体の学習機能の導入ではない。
