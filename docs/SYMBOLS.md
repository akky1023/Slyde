# 読みから入力する記号・絵文字

開発版では総合記号ボードを廃止し、その収録内容を変換辞書へ移しています。数字配列から開く記号1・2は、12キーの配置・編集・入力後の戻り方も含めて従来どおりです。左の「123」で数字配列、「あ／ABC」で文字配列へ切り替えます。

| 読み | 候補の例 |
| --- | --- |
| かっこ | （）、()、「」、『』、【】 |
| ひらきかっこ／とじかっこ | （／）、その他の開き・閉じ括弧 |
| やじるし／みぎやじるし | →、⇒など |
| はーと／ほし／おんぷ | ♥、★、♪など |
| のっといこーる／むげんだい | ≠、∞ |
| れいわ／へいせい | ㋿、㍻ |
| まるにじゅういち／まるごじゅう | ㉑、㊿ |
| てんじいちにさん | ⠇ |
| こくばんふとじおおもじえぬ | ℕ |
| ねこ／にほんこっき | 🐱、🇯🇵 |

## 辞書の範囲と候補順

元の総合ボード6,994件から肌色・髪色の派生1,896件を除き、表示指定を除去して重複をまとめた4,988種類を収録しています。慣習的な読み・括弧ペアとMozc辞書の候補は別途補完します。Unicode全体の文字を収録した辞書ではありません。通常の文章変換候補8件、記号・絵文字最大192件、残りの通常候補の順に、重複を除いて最大256件表示します。広い読みで一覧の後ろに隠れる記号は、個別名で変換できます。追加の記号辞書は読み全体が一致する場合だけ参照します。基本辞書にも記号が含まれるため、文章中のかなの一部分から記号へ置き換える経路は順位を下げ、通常の単語を優先します。「かっこをつける」などで括弧のペアを優先しません。句読点で読みが分かれた場合も同じ方針です。

記号の一般的な読みと括弧のペアを優先します。その後に個別名の候補を元の用途別順序で並べ、Mozcの既存の読みも補います。カタカナ・半角カナの読みはひらがなと同じ索引で引けます。

すべての辞書を読み込んだ後、Unicodeの明示的な半角・全角の対応116組を使い、同じ読みの不足する候補を補完します。「いげた」「なんばー」では＃と#、「えん」では￥と¥、「かぎかっこ」では「」と｢｣の両方を選べます。元の候補順を保ちながら、不足する側は対応する候補の隣に追加します。対象はASCII英数字・記号、句読点・括弧、通貨、一部の矢印・図形などです。半角カナ・ハングルの文字は補完しません。囲み数字や組み文字を通常の数字・単位に分解せず、国旗・キーキャップなどの結合列の一部も置き換えません。見た目が似ていても幅違いの対応がない記号（♯と#、〜と~、¥とバックスラッシュなど）は同一視しません。

E・Oの下フリックの括弧「（」「）」とその半角形からも、別の括弧の全角・半角を選べます。記号だけの変換候補は句読点・括弧の表示設定で書き換えず、選んだ候補の文字列をそのまま入力します。通常の文章候補では従来どおり句読点・括弧設定を反映します。

日本語名・読みの生成には次の資料を使います。

- [Unicode 16.0 UnicodeData.txt](https://www.unicode.org/Public/16.0.0/ucd/UnicodeData.txt)の英語名。CLDRに日本語名がない記号は、用語訳と囲み数字・組み文字・点字などの構造から日本語名を作ります。Unicode公式の日本語訳ではなく、専門名には逐語訳・音写を含みます。
- [CLDR 46の日本語注釈](https://github.com/unicode-org/cldr/tree/release-46/common/annotations)。2,356件に日本語名を使用し、絵文字ではキーワードの読みも追加します。
- `scripts/symbol-dictionary/conventional.tsv`の慣習的な読み。元号・数学記号・通貨・括弧などを補完します。
- Mozcの記号・絵文字辞書。固定版とライセンスは`input-core/src/main/resources/conversion/`に保持します。

## 表示と入力文字列

記号・絵文字の辞書候補からVS15・VS16を取り除き、「しゃーぷ」では`#`そのものを入力します。表示指定の違いだけで重複する候補は統合します。肌色修飾子・髪のコンポーネントを含む候補と、肌・髪の単独コンポーネントは除外し、標準の候補を残します。生成辞書と既存Mozc辞書の両方に同じ処理を適用します。

国旗・家族・職業などのZWJ結合列やキーキャップの結合文字は保持します。通常の文章や入力済み文字列にはこの整理処理を適用しません。文字／絵文字の見た目は端末・入力先のフォントに従います。

選択フォント、Noto Sans JP、Noto Sans Symbols、Noto Sans Symbols2、端末フォントによる補完は候補欄にも適用します。詳細は[フォント](FONTS.md)を参照してください。

## 再生成

生成物は`input-core/src/main/resources/conversion/unicode-symbols.tsv`です。アプリは生成済みTSVを読み込み、Python・通信・翻訳処理を必要としません。各行に読み・日本語名・英語名・出典を保持します。生成器は未訳の英単語が残る場合に失敗します。

同じ生成器で`width-variants.tsv`も生成します。UnicodeDataの`<wide>`・`<narrow>`だけを採用し、半角カナ・ハングルの文字を除外します。全辞書の該当する読みをテストで走査し、両方の幅が選べることを検証します。

Python 3とJDK 17を用意し、PowerShellで以下を実行します。`JAVA_HOME`はJDKのパスに設定してください。

```powershell
python -m pip install --target .tools/symbol-dictionary/python -r scripts/symbol-dictionary/requirements.txt
python scripts/generate-symbol-dictionary.py --fetch
```

入力データのURL・CLDRのコミット・SHA-256は`scripts/symbol-dictionary/sources.json`に固定します。`--fetch`は未取得のファイルをダウンロードし、ハッシュが異なるファイルは拒否します。生成時だけpykakasiで日本語名をかなへ変換します。用語訳は`unicode-terms.tsv`、慣習的な読みは`conventional.tsv`で修正できます。記号の収録範囲の情報源として`SymbolCatalog`を残しています。

全収録記号に日本語の読みがあること、元号・囲み数字・点字・素の記号・肌色と髪色の除外、通常変換の順位と候補数の上限をホストテストで検証します。辞書のライセンスはアプリの「このアプリについて」→「ライセンス」でも確認できます。
