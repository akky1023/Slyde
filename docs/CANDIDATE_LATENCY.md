# 候補表示の待ち時間（0.1.16）

入力後に必ず220ms待つ処理を削除し、次のメインループで読み・カタカナかキャッシュ済みの候補を表示します。辞書とzenzのどちらも相手を待たずに開始し、到着順に統合します。古い検索を途中で止め、同じ読みの再検索と候補セルの作り直しを減らしています。

## PC上の辞書検索

同梱辞書・JDK 17で同一の短文6件を各7回検索した中央値です。測定は辞書初期化後の `nBestPath(..., 12)` 単体で、Androidの描画やタッチ遅延は含みません。0msは1ms未満を切り捨てた値です。

| 読み | 変更前 | 変更後（キャッシュなし） |
| --- | ---: | ---: |
| き | 0ms | 0ms |
| きょ | 0ms | 0ms |
| きょう | 0ms | 0ms |
| にほん | 1ms | 1ms |
| がっこう | 4ms | 4ms |
| きょうはいいてんきです | 108ms | 92ms |

測定のばらつきがあるため、この表から検索アルゴリズム自体の高速化は主張しません。確実な変更は220msの固定待機をなくしたことです。新しいキャッシュで「にほん」「がっこう」「きょうはいいてんきです」を各1001回参照した中央値・95パーセンタイルは、いずれも1µs未満でした。これはキャッシュ取得だけの測定です。

途中キャンセル後の次の入力、キャッシュの上限と結果の不変性、辞書とAIの到着順が逆になった場合を回帰テストで確認します。

Androidの接続端末がないため、実機での入力から候補描画までの時間と操作感は未確認です。
