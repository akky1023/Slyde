# Glide 日本語入力

正式版APKは `dist/Glide-1.1.10.apk`、アプリIDは `net.neomenia.japaneseinput.glide` です。Android 8.0以降、arm64-v8a／x86_64に対応します。APKをインストールして設定アプリを開き、「キーボードを有効にする」「キーボードを切り替える」の順に操作すると、他のアプリで入力できます。

1.1.10では、LINEで「改行で送信」がOFFでもEnterで送信される不具合を修正しました。アプリの改行指定を独自の送信アクションより優先します。テスト版での実機確認済みです。

1.1.9では、IME右上の設定ボタンから「大きさ・位置」と「その他の設定」を選ぶ方式を復元しました。「大きさ・位置」では入力中のアプリを表示したまま枠を調整でき、「サイドバーの幅」で左右の青い境界バーをドラッグすると実際のキー幅へ即時反映されます。設定画面の文字・操作色は英字キーの青を基準にしたMaterial 3の配色と文字スタイルに統一し、候補欄の各行右端の区切り線を削除しました。

1.1.8ではアプリを設定専用にし、入力練習を削除しました。大項目は「入力」「変換」「表示」「このアプリについて」の4つで、記号入力ボードは「入力」、大きさ・位置は「表示」、ライセンスは「このアプリについて」にまとめています。設定画面のボタン・スイッチ・スライダーはMaterial Componentsを使用し、変更をその場で保存します（記号入力ボードと大きさ・位置は「保存」で確定）。サイドバー幅は色分けした図と左右のスライダーで調整でき、設定アイコンは6枚歯の歯車です。既存の設定値とキーボード本体の配列・見た目を維持します。

1.1.7では、候補文字を注記に左右されず区切り線の中央へ揃え、全角・半角などの注記を見分けにくい文字に絞りました。「二／ニ」「口／ロ」などには漢字・カナの注記を表示し、「幅可変」は表示しません。文字注記とAI表示は「表示とフォント」で個別にON/OFFできます。設定を項目別に分け、「大きさ・位置」に左右サイドバー幅の個別調整、中央寄せ、2本指のピンチによるサイズ変更を追加しました。

1.1.6では、変換候補の行高を文字サイズに応じて共通化し、日本語の字形を基準に縦中央へ配置します。Noto Sans JP・Bizin Gothic Discordでの大きな余白や位置のずれを抑え、全角・半角・AI注記は標準フォントで位置を揃えます。

1.1.5では、EU・IUの連母音が無効のときに途中のE・Iを無視し、KEU・KIUがどちらもKUになるよう変更しました。変換候補欄の高さは候補の文字サイズに合わせ、各行の余った横幅を候補へ均等に割り当てます。

1.1.4では、Nを2回タップした後の母音が「んあ」などになるよう修正しました。長文で候補探索が遅くなり順位も崩れていた経路探索を修正し、32文字で辞書変換を打ち切る制限を撤去しました。AI出力の前後空白を整理し、読みの一部を落とした候補を除外します。辞書の第一候補を保ち、AI候補を追加します。変換候補の文字サイズは設定で12〜30spに変更でき、通常・展開表示に共通で反映します。

1.1.3ではボトムバーの自動補正を撤去し、下余白をユーザーが枠の移動で調整する仕様に戻しました。通常表示でも非表示の調整ツールバー分を差し引いていたため、IMEの再計測でキーが縮む問題を修正しました。大きさ・位置のGUIは維持し、保存した高さを通常表示でも維持します。

1.1.2では、1.1.1の余白補正が表示位置を再計測してレイアウトを要求する循環を撤去しました。親から届くWindowInsetsだけで追加余白を決定し、値が変わらない場合は再レイアウトしません。練習画面が確保したバー領域も子へ重複適用しないようにしました。

1.1.1ではシステムのボトムバーを余白計算に反映しました。Androidが確保済みの分は重ねて加えず、キーボードに重なる分だけを確保します。調整中は下余白とバーの高さを別々に表示し、保存前後の基準を統一します。横画面の左右のバーも考慮します。

1.1.0では「キーの高さ」スライダーを削除し、実際のキーボードを枠のドラッグで移動・サイズ変更するGUIに置き換えました。変換候補がないときは候補欄右下に設定アイコンが表示され、「大きさ・位置」から入力先のアプリを開いたまま調整できます。枠の内側で移動、四隅・辺でサイズ変更し、「保存」「取消」「初期位置」を選べます。幅・高さ・左右位置・下の余白を縦／横画面ごとに保存します。下の余白は初期値24dp、最低12dpです。候補の展開・総合記号ボードも変更後の枠に収まります。

1.0.0では試作の入力・変換・記号・フォント設定を共通の処理にまとめ、AndroidのIMEとして登録しました。数字・電話・日時欄では数字配列、URL・メール・パスワード欄では英字配列で開始します。エンターは変換中なら確定、それ以外は検索・送信・次へなど入力欄の指定に従います。パスワード欄では変換候補を作成せず、記号履歴も保存しません。

正式版の専用署名鍵は `.tools/signing/` にあり、テスト版とは別の鍵です。署名・再ビルド・バックアップの説明と検証範囲は [リリース手順](docs/RELEASE.md) を参照してください。テスト版は `scripts/build-prototype.ps1` で作成でき、IDは `net.neomenia.japaneseinput.glide.debug`、表示名は「Glide 日本語入力 (テスト)」です。旧試作版の設定は別IDのため自動移行しません。

## 入力方法・開発履歴

日本語／英字で同じ12キー配列を使います。キーをタップ・フリックするか、`K→Y→O→U` などの経路をなぞってください。「あa」で日本語と英字、「⇧」で英字の大小文字を切り替えます。設定の「大きさ・位置」でキーボード全体を調整できます。「変換」または「空白」で基本辞書による変換候補を表示します。

0.1.1では、設定にNA寄り／NYA寄りの判定調整を追加しました。S→Kで数字配列へ、5→2で元の文字配列へ切り替えます。英字モードのA右フリックは `@`、Y右フリックは `_`。TYU・CHU・JUN、およびOUとOEの判定を調整しています。

0.1.2では、QA/QI/QU/QE/QOとCA/CI/CU/CE/COの変換を追加しました。S→K／5→2のフリックは、上端を越えて変換欄まで指が抜けても切り替わります。

0.1.6では、2本指でタップが重なっても押し始めた順に入力できるようにしました。Tを押してAを重ねると、離す順にかかわらず「た」と入力できます。

0.1.7では、英字のU下フリックを `'` に変更し、日本語の空白上フリックで全角空白を入力できます。数字配列の左下／右下は記号ボード1／2に切り替わります。設定で各ボードの12キーと、記号入力後に数字配列へ戻るかを変更・保存できます。記号ボードの「123」で数字配列へ戻ります。左右の機能キーを狭くし、英字キーを青色で表示してシフト状態に合わせて小文字／大文字を切り替えます。左上の記号ボタンは削除しました。

0.1.8では、左右の機能キーの幅を13%から15%へ広げ、記号1／2の空欄キーを数字配列への「戻る」ボタンに変更しました。左の「123」は「記号」になり、カテゴリ別の総合記号ボードを開きます。半角・全角記号、括弧、矢印、数学、通貨・単位、囲み文字、罫線に加え、Unicode Emoji 16.0の絵文字3,790件（肌・髪の単独コンポーネント含む）を入力できます。最近使った60件を保存します。総合記号ボードの「文字」「123」で文字／数字配列へ戻れます。絵文字の表示は端末のフォントに依存します。絵文字データの出典は [Unicode公式一覧](https://unicode.org/Public/emoji/16.0/emoji-test.txt)、ライセンスはアプリの設定から確認できます。

0.1.9では、設定でEU・IUの連母音を個別にON/OFFできるようにしました。初期値は両方ONです。総合記号ボードは右上に削除、左下に「戻る」、下中央に記号／絵文字切り替え、右下にエンターを配置し、上部のカテゴリを横スクロールに変更しました。「戻る」で開く前の配列に戻ります。

Sumireの基本辞書と同作者の基礎変換コードに、Mozcの記号・絵文字辞書を組み合わせています。「やじるし」「ほし」「かっこ」「はーと」「ねこ」などの読みからも候補を選べます。短い読みの候補を増やし、同じ読みの辞書項目を補完します。表示は最大256件で、長文の追加探索は抑えています。Android版Sumireの予測・学習機能全体を移植したものではありません。構成と版の情報は `sumire-engine/README.md`、入力仕様は `docs/INPUT_SPEC.md` を参照してください。変換はオフラインです。

0.1.10では、総合記号ボードのカテゴリと削除・エンター・左右カーソル・空白をSVG由来のアイコンに変更しました。「あa」の表記は日本語／英字で共通です。変換候補欄を試験的に追加し、入力中に候補を自動表示します。設定で1〜3行に変更・保存できます（初期値1行）。候補は横スクロールでき、タップで確定します。SVG原本は `prototype/artwork/icons/` にあり、`scripts/generate-icons.ps1` でAndroid用ベクターも再生成できます。

0.1.11では、変換欄を枠のない文字候補と区切り線のあるIME形式に変更しました。左から候補を並べ、2〜3行設定では画面幅で折り返します。右端の矢印で全候補をキーボード領域に展開・折りたたみできます。EU・IUのON/OFFは子音付きの連母音だけに適用し、母音だけのIUやE→Uの「！」には影響しません。

0.1.12では、総合記号ボードが変換候補欄の領域も使うようにしました。設定した候補欄の1〜3行分だけ一覧が広がり、「戻る」で元の候補欄に復元します。

0.1.13では、総合記号ボードを左右フリックでカテゴリ切り替えできるようにし、記号・変換候補の右下に全角／半角の注記を追加しました。設定で句読点・括弧の4種類と、IMEフォント（System／Noto Sans JP／Bizin Gothic Discord）を個別に変更・保存できます。Shiftはアイコン化し、1タップで次の英字入力を大文字、ダブルタップでCapsLockにします。フォントの配布元と同梱内容は `docs/FONTS.md` に記載しています。

0.1.14では、Shiftをタップごとの「一時Shift→CapsLock→解除」に変更し、ダブルタップ判定を削除しました。変換候補は通常時と展開時で同じビューを使い、開いたときに同じ候補が二重に表示されないようにしました。

0.1.15では、Shift有効時をアイコンの塗りつぶしで表示します。また、zenz v3.2 xsmallによるオフラインAI変換を追加しました。辞書候補を先に表示し、推論完了後に「AI」付き候補を追加します。設定でON/OFFできます（初期値ON）。モデルの固定版・ライセンス・実推論の確認範囲は `zenz/README.md` に記載しています。

0.1.16では、候補検索前の220ms固定待機を削除しました。読み・カタカナとキャッシュ済み候補を即時表示し、辞書とzenzを並列に更新します。古い辞書検索の途中キャンセル、辞書128件／AI32件のキャッシュ、候補セルの再利用で連続入力時の待ちと再描画を減らしました。検証範囲は `docs/CANDIDATE_LATENCY.md` に記載しています。

ビルドは初回に `scripts/prepare-zenz.ps1` を実行し、その後 `scripts/build-prototype.ps1` にJDK 17とSDKのパスを指定して実行します。NDK 28.2.13676358とCMake 3.22.1も必要です。実録9軌跡の回帰テストと、同梱する実辞書での変換テストを含みます。

アルテを使って入力した結果と編集履歴を記録するAndroidアプリと、USB経由で画面録画・タッチ軌跡を保存するPCツールです。新しいIMEの入力規則と回帰テスト用の資料を集めます。

## 使い方

1. Galaxy S25でUSBデバッグを有効にし、PC接続を端末で承認します。アルテは普段の設定・サイズ・配列のまま使います。
2. Python 3.10以降とADBを使えるPCで、プロジェクトフォルダから以下を実行します。初回の `-Install` は同梱の記録アプリをインストールします。

```powershell
.\scripts\record.ps1 -Install
```

Windowsでは `start-recording.cmd` をダブルクリックしても開始できます。このPCではCodexに同梱されたPythonも自動検出します。

3. 端末の「アルテ入力記録」で「IME選択」からアルテを選びます。「例題」で入力対象を選んで「記録開始」を押します。
4. 指示された文字を入力します。入力方法は普段どおりで構いません。「次の例題」で現在の結果を保存し、入力欄を空にして次へ進みます。
5. 英字の例題でもアルテ配列を使ってください。「自由入力」では任意の目標文字を設定できます。日本語の変換を試す場合は、自由入力の目標に漢字を指定してください。
6. 終了時はアプリで「記録停止」、PCで **Ctrl+C** を押します。録画の終了とファイル回収が済むまでUSBを抜かないでください。

複数端末がある場合は `-Serial 端末のシリアル` を指定します。`-Python` と `-Adb` で実行ファイルのパスを指定できます。ADBの接続確認は `adb devices -l` です。

記録済みのアプリログだけを後から再回収する場合：

```powershell
.\scripts\record.ps1 -CollectOnly
```

アプリ単体でも記録できます。「書き出し」で全セッションをJSONLとして保存できます。未確定のままの入力も記録するため、例題の最後に必ず確定する必要はありません。

## 保存内容

`captures/日時/` に保存します。

| ファイル | 内容 |
| --- | --- |
| `screen-001.mp4` 以降 | 画面全体の録画。ポインタの軌跡表示付き。約170秒ごとに分割 |
| `screen-start.png` / `screen-end.png` | 録画前後のスクリーンショット |
| `metadata.json` | 解像度・密度・入力デバイスの座標範囲・時計対応・録画区間・取得エラー |
| `display.txt` | 端末の表示設定・回転・表示モードなど |
| `input-devices.txt` | 入力デバイスと座標範囲 |
| `getevent.txt` | タッチイベントの原文。取得失敗の理由も確認可能 |
| `touches.jsonl` | 解析したマルチタッチの座標・指ID・指を離したタイミング |
| `sessions/*.jsonl` | 入力文字・選択範囲・未確定範囲・IME編集命令・例題と実際の結果 |

画面録画は固定サイズへの縮小を指定せず、端末の `screenrecord` の既定サイズを使います。録画機能の制約により実際の動画サイズが画面サイズと異なる場合があるため、動画の実寸と `metadata.json` を併用してください。動画の分割の間には短い欠落があり、その間の映像は復元できません。長い操作は分割境界を避けて再記録してください。

生のタッチ座標は画面のピクセルとは限りません。`rawX/rawY` を保持し、入力デバイスの最小・最大値に基づく `normalizedX/normalizedY`（パネル全体に対する0〜1）も保存します。これらは**キーボード内の正規化座標ではありません**。端末の回転やキーボードの高さ・左右寄せを映像で確認してから、キーボードの矩形に合わせてテスト座標へ変換します。アプリは縦画面を指定します。

アプリの記録中表示には `t=...ms`（端末のuptime）を100msごとに表示します。これを動画内で読めば、入力ログの `uptimeMs` と照合できます。IME呼び出しの回数と指の操作回数は同じとは限りません。動画とタッチのDOWN/UPに相当する追跡IDの開始・終了を併せて判断します。動画とタッチのフレーム単位の自動同期は未実装です。PC側時刻はプロセス開始・終了の範囲であり、厳密な動画PTSではありません。入力位置のインデックスはUTF-16です。

例題の `matchesExpected` は表示された文字列の一致だけを判定します。操作が正しかったことや、変換が確定済みであることは保証しません。全セッションを回収するので、今回の分は `sessionStart` の日時とセッションIDで識別できます。

## 端末による制限と復旧

起動に失敗した場合は、画面に出る原因と `captures/launcher-日時.log` を確認してください。端末が見つからない場合はデータ通信可能なUSBケーブル・USBデバッグ設定を確認し、未承認の場合は端末のロックを解除してPCからの接続を許可します。エラーを報告する際はこのログを添えると、元のADB・Pythonのエラーを確認できます。

通常のアプリは、別のIME上のタッチ軌跡を直接受け取れません。このツールはADBの `getevent` を試し、許可されない端末では数値の軌跡を取得できません。その場合も、ポインタ表示を付けた画面録画と編集履歴を残します。root取得は行いません。Galaxy S25で実際に許可されるかは端末接続後の確認が必要です。

USB記録中だけAndroidの「ポインタの位置」「タップを表示」を有効化し、正常終了・Ctrl+C時は元の値へ戻します。アプリ自身は通信権限を持ちません。PCの記録中は端末の画面とタッチ全体が記録対象になるため、テスト画面で操作してください。

PCの強制終了やUSB切断で復元できなかった場合、Androidの開発者向けオプションで表示を戻せます。録画の回収に失敗した場合は `metadata.json` の各区間の `remote` に端末側のファイルパスを残します。再接続して `adb pull そのパス 保存先` で回収できます。回収成功前の録画を端末から自動削除しません。
